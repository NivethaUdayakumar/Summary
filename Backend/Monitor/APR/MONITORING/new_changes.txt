APR per-batch command file changes

| File | Functions Changed | What Changed |
| --- | --- | --- |
| `Backend/Monitor/APR/MONITORING/APR_MONITOR_ITEMS.py` | `get_runtime_paths()`, `refresh_runtime_context()` | Replaced the single `BATCH_FILES.txt` runtime path with the `EXTRACTORS/BATCH_COMMANDS` directory path and ensured that folder exists every monitor cycle. |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `_get_runtime()`, `reconcile_batches()`, `shutdown_runtime()`, `_dispatch_ready_batches()` | Added slot tracking for parallel batch files, released slot files after completion, reset the managed command-file pool based on `MAX_PARALLEL_BATCHES`, and allowed short batches to launch after `BATCH_RUN_WAIT_TIME` whenever a parallel slot is free. |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `_submit_batch()`, `_requeue_batch_items()`, `_claim_batch_slot()`, `_release_batch_slot()`, `_get_batch_command_file_path()` | Changed batch submission to claim one dedicated file per batch job from `EXTRACTORS/BATCH_COMMANDS`, submit that file through `utilq`, and return the slot when the batch finishes or submit fails. |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `_sync_batch_command_slots()`, `_reset_batch_command_files()` | Added the logic that deletes old managed batch command files and recreates exactly one file per configured parallel batch slot. |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `_build_batch_file_lines()`, `_write_batch_file()`, `_build_batch_command()` | Updated the batch file writer and submit command builder so each slot file contains the module-load line plus one `python3` command per queued run, then launches `utilq -Is source <slot_file>`. |

APR batch status and error handling changes

| File | Functions Changed | What Changed |
| --- | --- | --- |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `get_validation_error_code()`, `check_valid_job()`, `_mark_file_item_invalid()` | Updated APR validation handling so `ERR001` means job failed, `ERR002` means KPI file missing, and `ERR003` means no timing reports found. Older persisted `ERR001` extraction-failure state is normalized to `ERR003` so existing monitor state keeps the right meaning. |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `reconcile_batches()`, `_finalize_ready_batch_items()`, `_finalize_batch()` | Added per-item completion checks for running batches so each APR run moves to `Completed` as soon as its timing DB is created, without waiting for the whole batch process to finish. Batch completion accounting now keeps the original submitted count while tracking already-finished items separately. |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `_build_batch_item()`, `_mark_batch_items_extracting()`, `_push_batch_item_tracker_state()` | Expanded batch payloads with the data needed to rebuild tracker rows and immediately push tracker updates for every item in a submitted batch. This fixes the issue where only one file appeared as `Extracting` even though the whole batch had already been sent. |
| `Backend/Monitor/APR/MONITORING/APR_STATUS_ACTION.py` | `shutdown_runtime()`, `_set_success_state()`, `_set_failure_state()`, `_set_await_state()` | Updated shutdown and batch-finalization paths to return the updated state entry and reuse it for immediate tracker writes. Completed runs now stay complete when the monitor stops, while unresolved extracting or pending runs are reset back to `Await Extraction`. |
| `Backend/Monitor/APR/MONITORING/APR_ITEM_STATUS.py` | `compute_status()` | Adjusted persisted-status recovery so `ERR001` and `ERR002` hold the run in `Job Failed`, while `ERR003` holds the run in `Extraction Failed` until the input files change. |
| `Backend/Monitor/APR/MONITORING/APR_UPDATE_TRACKER.py` | `apply_kpi_status()`, `update_tracker()` | Kept completed runs in `Completed` once their timing DB exists. KPI extraction still fills the tracker row, but missing KPI values now stay as comment `ERR002` instead of downgrading the run out of `Completed`. |
